# 01 - Requirements

本文件定义 JWord 要解决的问题、必须具备的能力和明确不做的范围。

## 1.1 用户与场景

### 集成方

集成方是在已有系统中嵌入文档编辑能力的开发团队，例如合同管理、标书管理、知识库、OA、CRM、教育平台、AI 写作系统。

集成方需要：

- 用 JavaScript/TypeScript 直接集成编辑器。
- 控制文档保存、资源上传、用户权限、协同服务和审计。
- 对接 React/Vue，但不希望编辑器核心绑定任何框架。
- 能导入/导出 docx/PDF，避免用户在在线编辑器和 Microsoft Word/WPS 之间来回丢格式。

### 最终用户

最终用户是使用 JWord 编辑文档的人。核心需求是：

- 像 Word 一样看见分页、页边距、表格、图片、页眉页脚和页码。
- 中文输入、复制粘贴、撤销重做、查找替换、批注、修订都稳定。
- 多人协同不丢内容，不因为 AI 自动插入打断手动编辑。
- 导出的 PDF/docx 与编辑时视觉结果尽量一致。

## 1.2 产品范围

JWord 必须提供：

- 编辑器内核：文档状态、事务、选择区、命令、历史、排版、渲染、输入。
- 原生 UI：工具栏、菜单、批注栏、状态栏、基础对话框。
- 互通包：docx 导入导出、PDF 导出。
- 协同包：Yjs binding、awareness、离线恢复、示例服务。
- 自动插入 API：面向 AI/模板/程序化内容写入。
- 适配包：React、Vue 3；Vue 2 可作为兼容包延后。
- 示例：vanilla、React、Vue、collab、docx、performance。

JWord 不负责：

- 账号、组织、权限模型、鉴权 UI。
- 文档列表、文件夹、回收站、审批流。
- 服务端生产级部署、运维、审计、日志平台。
- 宏系统、邮件合并、复杂公式编辑器。
- Excel/PPT 编辑能力。

## 1.3 功能需求

### 基础编辑

必须支持：

- 光标、选区、点击定位、拖拽选区。
- 文本输入、删除、回车、方向键、复制、剪切、粘贴。
- 中文 IME 输入，至少覆盖 macOS 和 Windows 的主流输入法。
- 撤销/重做，覆盖输入、删除、格式、段落拆分合并、表格基础操作、图片插入、批注。
- 安全纯文本粘贴；保格式粘贴必须经过 HTML 清洗。

### 文字与段落样式

必须支持：

- 加粗、斜体、下划线、删除线、上标、下标。
- 字体、字号、文字颜色、背景色。
- 段落对齐、行距、段前段后、左右缩进、首行缩进、悬挂缩进。
- 有序列表、无序列表、多级列表。
- 超链接。

### 分页排版

必须支持：

- A4、Letter 等常用纸张，纵向/横向，页边距。
- 编辑期真实分页，不能只在导出时分页。
- 手动分页符、分节符。
- 页眉页脚、页码。
- 缩放、页面阴影、分页预览。
- 移动视口下分页预览可阅读。

### 块级结构

必须支持：

- 图片插入、预览、上传替换、尺寸调整。
- 简单表格：插入、删除行列、合并单元格、基础边框、单元格内文本编辑。
- 目录生成，基于标题结构。
- 批注：添加、回复、解决、定位、侧边栏展示。
- 修订：插入、删除、格式修改记录；接受/拒绝可进入 post-1.0 深化。

### 格式互通

必须支持：

- docx 导入：T1 覆盖段落、run 样式、列表、简单表格、inline 图片。
- docx 导出：从 JWord model 生成 OOXML，Word/WPS/LibreOffice 能打开。
- T2 目标：页眉页脚、分页符、批注、超链接、简单浮动对象和常用企业模板。
- PDF 导出：基于同一 LayoutBox，支持中文字体外置配置。
- Worker import/export：可取消、可进度回调、主线程不阻塞。

### 协同与持久化

必须支持：

- 多人实时协同编辑。
- 远端光标、远端选区、在线状态。
- 离线编辑，本地恢复，联网后合并。
- 服务端 update log 和 snapshot 接口规范。
- 历史版本基于协同 update/snapshot，不以 docx 覆盖文件作为真源。

### 自动插入

必须支持：

- `createInserter()` 创建程序化插入通道。
- 自动插入与手动编辑共享同一文档状态和事务管线。
- 自动插入位置使用稳定锚点，用户在其他位置编辑不导致漂移。
- 自动插入默认不进入用户 undo 栈，可配置独立 undo 行为。
- 支持 throttle、flush、abort、progress、error。

### 插件与框架适配

必须支持：

- 插件注册、卸载、命令扩展、菜单扩展、装饰层扩展。
- 资源上传适配、保存适配、协同 provider 适配。
- Vanilla API 为基线。
- React/Vue wrapper 只负责生命周期和事件桥接，不持有编辑状态。

## 1.4 非功能需求

- Core 不依赖 React/Vue，不在 top-level 访问 DOM。
- API 面向 TypeScript 用户，公开 API 必须有类型和 TSDoc。
- 首屏 bundle 不包含 docx、PDF、collab、React/Vue wrapper。
- 大文档能力必须由 benchmark 证明，不能只写目标数字。
- 错误必须可恢复、可上报、可诊断。
- 安全策略必须覆盖粘贴、链接、图片资源、docx import、HTML 片段。

## 1.5 明确延期项

以下能力不进入 `1.0-stable` 强承诺：

- 完整修订互通和复杂审阅流。
- 脚注、尾注、交叉引用、题注。
- 复杂浮动对象、文本框、艺术字。
- 复杂表格布局和 Word 所有边界兼容。
- 自研 OT 替换 Yjs。
- Chrome Extension devtools。
- Vue 2 深度维护。
